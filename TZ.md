# ТЗ: «Kraków bez barier» — платформа доступных и разгруженных туристических маршрутов

> ТЗ написано на русском для команды. Все тексты интерфейса, презентация и видео — **на польском** (требование организаторов).

## 0. Сроки и команда
- Команда: 3 человека.
- **Этап 1 — прототип до 20:00 (сегодня):** только Flutter, без бэкенда. Данные берутся из Overpass/ORS и локальных JSON с пометкой «DANE PRZYKŁADOWE».
- **Этап 2 — финал до 11:00 (завтра):** бэкенд на Java Spring Boot + PostGIS, ИИ-анализ фото, PDF до 10 слайдов, видео до 3 минут в открытом репозитории.

## 1. Проблема и цель
Людям на инвалидной или детской коляске метки «dostępne/niedostępne» мало. Им нужны конкретные данные: ступени, бордюры, покрытие, ширина двери, туалет, места для отдыха. Плюс нужно понимать, насколько эти данные свежие и надёжные. Отдельная проблема — туристические толпы: в переполненном месте на коляске проехать ещё труднее.

**Цель:** приложение, которое
1. показывает детальную доступность мест и маршрутов с учётом **индивидуальных порогов** пользователя;
2. строит маршрут, который **распределяет людей** по городу (обходит переполненные квадраты);
3. через игровую механику (существа + ваучеры) **мотивирует людей картировать барьеры** и уходить в менее загруженные районы.

### Соответствие критериям жюри
| Критерий (вес) | Чем закрываем |
|---|---|
| Польза для группы, удобство (25%) | Профиль порогов, детальная карточка места, текстовый список вместо карты, маршрут без барьеров |
| Качество прототипа (20%) | Рабочий демо-сценарий на реальных данных OSM |
| Достоверность данных (15%) | У каждого факта есть источник, дата и уровень доверия; конфликтующие данные показываются явно; «brak danych ≠ dostępne» |
| Внедрение и масштабирование (20%) | Адаптеры источников; новый город = bbox + конфиг; docker-compose |
| Бизнес-модель (20%) | B2B-бейдж, ваучеры по модели CPA, API/виджет, white-label, аналитика толп |

## 2. Целевая группа и профиль потребностей

- **Родители с детскими колясками.**
- Приложение **не спрашивает об инвалидности**, только о предпочтениях (по требованию PDF). Пресеты: «Wózek inwalidzki», «Wózek dziecięcy», «Własne».

## 3. Пользовательские сценарии
**Главный демо-сценарий:**
1. Onboarding → выбор пресета «Wózek inwalidzki».
2. Поиск «Wawel» → карточка места: список барьеров и удобств, у каждого источник, дата и значок доверия.
3. «Zaplanuj trasę» из Rynek, Kazimierz, Wawel → маршрут обходит ступени и высокие бордюры, порядок остановок подстроен под толпу («Wawel teraz zatłoczony — przesunięty na 16:00»).
4. Переключение «Pokaż jako listę» → весь маршрут в текстовом виде (для скринридера).
5. На маршруте появляется существо → фото места → ИИ отмечает «4 schody, brak rampy, krawężnik >7 cm» → факт попадает на карту со статусом «AI · niezweryfikowane».
6. Очки → ваучер в кафе в малолюдном квадрате, таймер 2 ч.

**Обязательные краевые сценарии (по PDF, раздел 6):**
- **Конфликт данных:** OSM говорит `wheelchair=yes`, пользователь сообщает «3 schody». Показываем оба факта и предупреждение «Dane sprzeczne — sprawdź przed wizytą».
- **Нет данных:** серый статус «Brak danych o dostępności». Такое место **никогда** не засчитывается как доступное, при маршрутизации получает штраф.
- **Источник недоступен** (Overpass вернул 429 или таймаут): берём кэш, показываем баннер «Dane z dnia 03.10.2026, 14:20 — źródło chwilowo niedostępne».
- **Устаревшие данные** (старше 12 месяцев): статус «Nieaktualne» и кнопка «Potwierdź aktualność».

### 4.2 Karta miejsca (детали)

### 4.3 Trasa
- P0: маршрут из 2–5 точек через OpenRouteService, профиль `wheelchair`. Параметры профиля передаются в `restrictions`: `maximum_incline`, `maximum_sloped_kerb`, `minimum_width`. Покрытие (брусчатку) не учитываем.
- P0: список сегментов с предупреждениями («Odcinek 3: schody, 4 stopnie»).
- P1: **перебалансировка порядка остановок** по толпам:
  - стоимость = Σ(время пути) + λ · Σ(crowd(cell, ETA) · время в точке);
  - перебор всех перестановок при ≤6 точках, иначе жадный алгоритм + 2-opt;
  - пересчёт каждые 10 минут или по кнопке «Przelicz wg tłumów».
- P1: «rozproszenie» — разным пользователям с одинаковым запросом даём разные, но равноценные варианты: случайность в пределах +10% стоимости с учётом числа уже выданных маршрутов в квадрат.
- P2: групповые прогулки.

### 4.4 Złap / Zgłoś (камера)
- P1: фото → Java API → **Python-сервис (FastAPI, компьютерное зрение)** → **Gemini API (Flash, structured output)** → JSON:
  `{steps:int?, kerb_range:"0-3"|"3-7"|">7"|null, width_range:"<70"|"70-90"|">90"|null, ramp:bool?, handrail:bool?, obstacles:[...], difficulty:0-10, confidence:0-1}`.
  Сантиметры по одному фото не измерить, поэтому ИИ возвращает **диапазоны**.
- Python-сервис до вызова Gemini (OpenCV, Pillow, imagehash):
  1. проверка качества (смазано или темно → «Zrób zdjęcie ponownie»);
  2. уменьшение до ~1280 px, удаление EXIF после чтения GPS и времени;
  3. perceptual hash против дубликатов (одно и то же место);
  4. размытие лиц и номеров (детектор OpenCV, P1/P2).
- P2: YOLO-детектор ступеней и бордюров как второе мнение. Если он и Gemini расходятся → «niepewne».
- P0 (прототип): ручная анкета с чекбоксами барьеров (fallback для режима без ИИ).
- Проверки: GPS ≤ 50 м от точки спавна; время в EXIF не старше 10 минут.
- Gemini free tier может использовать данные для обучения: для демо допустимо, в продакшене — платный тариф.

### 4.4.1 Как считаются метрики
| Параметр | OSM (Overpass) | Фото + ИИ | Ручной отчёт |
|---|---|---|---|
| Ступени | `highway=steps` + `step_count`; у входа `entrance` + `wheelchair`, `step_count` | число видимых ступеней | «ile schodów» |
| Бордюр | `kerb:height`, либо тип: `flush`=0, `lowered`≈2, `rolled`≈4, `raised`≈12 см (помечается «szacunek z typu») | диапазон 0–3 / 3–7 / >7 см | диапазон |
| Ширина | `width`, `door:width` | <70 / 70–90 / >90 см | диапазон |
| Уклон | `incline`; если нет — расчёт по модели рельефа (NMT/LiDAR geoportal.gov.pl или MSIP): Δвысоты / длина, «Szacunek (model terenu)» | — | stromo / łagodnie / płasko |
| Удобства | `toilets:wheelchair`, `ramp`, `elevator`, `amenity=bench`, `parking_space=disabled` | пандус, поручень | чекбоксы |

**Оценка:** по каждому параметру берём худший достоверный факт и сравниваем с порогом профиля → пройдено / на грани (±20%) / не пройдено / нет данных.
- Критичные параметры (ступени, бордюр, ширина) не пройдены → «Nie pasuje».
- Не пройден некритичный параметр (уклон) или что-то на грани → «Częściowo».
- Нет данных по критичному параметру → «Za mało danych».
- Всё пройдено → «Pasuje».

## 5. Модель достоверности данных
Каждый факт хранится в виде `AccessibilityFact`:
```
feature   (steps | kerb_height | door_width | ramp | elevator | toilet | bench | incline ...)
value
source    (OSM | MSIP | OTWARTE_DANE | OWNER | USER | AI | ESTIMATE)
source_ref (id объекта OSM / id отчёта / URL набора данных)
fetched_at, confirmed_at, confirmations_count, disputes_count
trust     (вычисляется)
```
| Уровень | Условие | Отображение |
|---|---|---|
| ✅ Potwierdzone | владелец объекта ИЛИ OSM + ≥2 независимых подтверждения ИЛИ ≥3 пользователя | зелёная галочка + «Potwierdzone (5 osób, 2 dni temu)» |
| 🟦 Dane otwarte | OSM / MSIP / Otwarte Dane без подтверждений | «OpenStreetMap, edycja 12.2025» |
| 🟨 Zgłoszone | 1 отчёт пользователя | «Zgłoszenie użytkownika — niezweryfikowane» |
| 🤖 AI | только ИИ-анализ | «Ocena AI — niezweryfikowane» |
| ⚠️ Sprzeczne | есть противоречащие факты | показываем все + предупреждение |
| ⌛ Nieaktualne | старше 12 месяцев | серый текст + «Potwierdź» |
| ⬜ Brak danych | фактов нет | «Brak danych» (≠ dostępne) |

**Исправление ошибок:** «Zgłoś błąd» создаёт спорный отчёт (dispute). При ≥2 спорах значение понижается до «Sprzeczne». Новые отчёты пользователей можно отправлять обратно в OSM в виде заметок (OSM Notes, P2).

**Итоговая оценка места или сегмента для профиля** = худший из **достоверных** фактов по каждому параметру профиля. Если для критичного параметра данных нет, результат «Za mało danych», а не «Pasuje».

## 6. Толпы (Crowd model)
Город делится на сетку 250×250 м (в Кракове около 5–6 тыс. квадратов; для MVP — центр, около 400).

**crowd(cell, t) ∈ [0..1]** складывается из трёх слоёв:
1. **Базовая оценка (всегда есть):** `base = norm(Σ веса POI в квадрате) × hour_profile[type][dow][hour]`. Веса POI из Overpass: `tourism=attraction` 5, `historic=*` 3, `amenity=restaurant|cafe|bar` 1, `public_transport=stop_position` 1. Часовые профили — эвристика, по типам места (музей, ресторан, площадь). Помечается «Szacunek».
2. **Опрос «Jak tłoczno?»** — одно касание (🟢 / 🟡 / 🔴) при входе в квадрат или в карточке места. Вес ответа затухает экспоненциально, полураспад 30 минут. За ответ +5 очков, не чаще одного раза в квадрат за 30 минут.
3. **Активные пользователи приложения** в квадрате (анонимно, агрегировано, без истории перемещений).

Итог: `crowd = w1·base + w2·survey + w3·live`. Веса зависят от свежести и количества данных. В UI всегда виден источник: «Szacunek (OSM + pora dnia)» или «12 osób zgłosiło, ostatnio 8 min temu».

**Источники, которые проверить в первую очередь** (из списка PDF): otwartedane.um.krakow.pl и MSIP — счётчики пешеходов и велосипедистов, календарь мероприятий, загрузка паркингов. Найдётся что-то — добавляем четвёртым слоем-адаптером.
**Не используем:** Google Popular Times, Yandex, Apple Maps, Snap Map — нет публичного API или запрещено ToS. В PDF, стр. 6: «samo opublikowanie… nie oznacza, że wolno ją automatycznie pobierać». BestTime.app — платный адаптер в roadmap (P2).

## 7. Игровая механика
### 7.1 Спавн существ
- Квадрат получает `difficulty(cell)` ∈ [0..1] из OSM: доля сегментов со ступенями, высоким бордюром, крутым уклоном; объекты с `wheelchair=no/limited`.
- **Потенциально трудные места** определяются тремя способами:
  1. OSM-теги (ступени, `kerb=raised`, `incline>6%`, `wheelchair=no`);
  2. **дыры в данных**: POI без тега `wheelchair` и переходы без `kerb` — там картировать полезнее всего;
  3. отчёты пользователей и приманки.
- Вероятность спавна в точке пропорциональна difficulty + бонус за «неизвестность» (brak danych).
- **Редкость:** `rarity_score = 0.5·difficulty + 0.3·unexplored + 0.2·low_crowd`, где `unexplored = 1 / (1 + число фото в радиусе 30 м)`. Пороги: <0.35 common, <0.6 rare, <0.8 epic, иначе legendary. Повторное фото того же места **понижает** редкость.
- Нагрузка на точку ограничена: после N подтверждений существа там больше не появляются, место считается закартированным.

### 7.2 Приманка (Przynęta)
- Стоит 50 очков. Пользователь ставит её там, где, по его мнению, есть барьер. Шанс спавна в радиусе 50 м растёт в 3 раза на 24 часа. Если кто-то сделает там подтверждённое фото, автор приманки получает +30% очков.

### 7.3 Антиабуз
- Кулдаун 30 м / 1 спавн в 15 минут на пользователя; GPS-проверка; EXIF и время съёмки; perceptual hash; лимит фото в сутки; детект «телепортации» (скорость между событиями больше 30 км/ч — подозрительно).
- Если ИИ ответил с confidence < 0.5, очки делятся пополам до подтверждения.

## 8. Очки и ваучеры
- Очки не сгорают. Common 10, rare 25, epic 60, legendary 150, опрос толпы 5, подтверждение чужого факта 15.
- **Ваучер** покупается за очки в любой момент. **После активации** действует 2 часа (подталкивает пойти сейчас и туда).
- **Квота ваучеров на точку** = `base_quota × (1 − crowd(cell))`, пересчёт каждые 15 минут. Где пусто — больше ваучеров, на Rynek в пиковое время — почти ноль.
- Партнёр задаёт скидку, base_quota и часы. Попасть в программу можно только с **подтверждённой доступностью входа** (проверяется по разделу 5). Это стимул для заведений улучшать доступность.
- Прототип: партнёры и ваучеры — демо-данные с пометкой «DANE PRZYKŁADOWE».

## 9. Архитектура
```
[Источники]                    [Ingest / адаптеры]           [Ядро]                      [Клиенты]
Overpass API  ─┐               OverpassAdapter      ─┐
MSIP WFS      ─┤──►            MsipAdapter          ─┤──►  AccessibilityFact (PostGIS) ──► REST API ──► Flutter app
Otwarte Dane  ─┤               OtwarteDaneAdapter   ─┤      CrowdGrid                       │           (Android / Web)
Пользователи  ─┤               UserReportService    ─┤      Spawn / Rewards                 └──► (P2) виджет / API B2B
Фото → Python CV ─► Gemini ─┘  AiPhotoService       ─┘      RoutingService ──► OpenRouteService
```
- **Отделение данных от представления** (требование PDF): адаптеры реализуют интерфейс `SourceAdapter { fetch(bbox) → List<AccessibilityFact> }`. Новый источник = новый класс + запись в конфиге.
- **Новый город** = запись `City{name, bbox, timezone, grid_size, enabled_adapters}` + запуск импорта. Код не меняется.
- **Новая категория мест** = маппинг тегов OSM → feature в YAML.
- **Обновление:** Overpass — раз в сутки (diff по `timestamp`), MSIP и Otwarte Dane — раз в неделю, толпы — каждые 5 минут.
- **Недоступность источника:** 3 ретрая с экспоненциальной задержкой, затем последний кэш + флаг `stale` в API → баннер в UI.

### 9.1 Этап 1 (прототип, без бэкенда)
- Flutter обращается к Overpass (запросы по bbox центра, ответ кэшируется в `shared_preferences`/файл) и к ORS (ключ в `--dart-define`, только для демо).
- Снимок данных Overpass для центра лежит в `assets/data/osm_center.json` — fallback, если API недоступен.
- Демо-толпы, партнёры и существа — в `assets/demo/*.json`, в UI бейдж «DANE PRZYKŁADOWE».
- Абстракция `Repository` с реализациями `LocalRepository` (этап 1) и `ApiRepository` (этап 2), UI не меняется.

### 9.2 Этап 2: бэкенд Java Spring Boot + PostGIS
- Java 21, Spring Boot 3, Spring Web, Spring Data JPA + **Hibernate Spatial** (JTS, SRID 4326), Flyway, Spring Security (анонимный JWT: устройство получает токен без регистрации), `@Scheduled` (импорт и пересчёт сетки), Bean Validation, springdoc-openapi (Swagger).
- Хранение фото: локальный том, P2 — MinIO/S3.
- Анализ фото — отдельный контейнер `vision` (Python 3.12, FastAPI, OpenCV, imagehash, google-genai). Java вызывает его по внутренней сети, наружу он не открыт. Ключ Gemini хранится только в `vision`.
- `docker-compose.yml`: `postgis/postgis:16-3.4` + `app`. Деплой на Railway или Render. **Прогреть инстанс перед демо** (холодный старт).
- CORS для Flutter Web.

**Подводные камни, которые учесть:**
- SRID: везде 4326, `ST_DWithin` по `geography`, иначе расстояния будут в градусах.
- GIST-индексы на всех геометриях.
- Rate limit у Overpass: импорт идёт одним запросом по bbox, а не по запросу на каждого пользователя.
- Лимиты ORS на бесплатном ключе (около 2000 запросов в сутки): маршруты кэшировать.
- Размер фото: сжимать на клиенте до ~1280 px и JPEG 80%.

### 9.5 Промпт ИИ (сервер)
Модель: Gemini Flash (актуальная версия, режим `response_schema`), вызывается из Python-сервиса `vision`. Системный промпт задаёт роль аудитора доступности и **строгий JSON** из раздела 4.4. Правила: «если не видно — null, не выдумывай», confidence оценивается честно. Ответ валидируется по схеме; если невалиден — 1 ретрай, затем статус «AI niedostępne, użyj ankiety».

## 11. Приватность и безопасность
- Анонимная учётка (токен устройства), без email и **без вопросов о здоровье и инвалидности**.
- Профиль потребностей хранится только на устройстве.
- GPS используется только в момент события (фото или опрос), треки не храним. Толпы агрегируются по квадратам, минимум 3 пользователя, иначе не показываем.
- EXIF удаляется после проверки; P2 — размытие лиц и номеров.
- Только HTTPS; rate limiting на API; модерация отчётов (жалоба → скрытие при ≥3 жалобах).
- Соответствие RODO: политика приватности, удаление данных по запросу.

## 13. Бизнес-модель
1. **B2B для заведений:** бейдж «Zweryfikowana dostępność» + профиль на карте + участие в ваучерной программе. Подписка 49–149 zł в месяц.
2. **Ваучеры — CPA:** партнёр платит 1–3 zł за погашенный ваучер. Ценность для партнёра — гости в непиковые часы.
3. **API и виджет доступности** для отелей, организаторов событий, систем бронирования: «доступность вокруг объекта», маршрут от отеля. Тарифы по числу запросов.
4. **White-label для городов и DMO:** аналитика толп и карта барьеров (где вкладываться в ремонт) — лицензия на год.
5. **Организаторы мероприятий:** временный слой доступности для события.
- Себестоимость MVP: хостинг около 50–100 zł в месяц, ИИ около 0,01–0,03 zł за фото.

## 14. Внедрение и сопровождение
- **Ответственный:** команда в форме стартапа (sp. z o.o.). Хостинг у облачного провайдера в ЕС, данные не на инфраструктуре UMK.
- **Обновление данных:** автоматические адаптеры + сообщество. Город ничего не поддерживает вручную.
- **Обработка отчётов:** модерация силами сообщества + админ-панель (P2).
- **Новый город:** добавить bbox и конфиг → импорт OSM → часовые профили по умолчанию → привлечь 5–10 партнёров. Около 1 дня технической работы.
- **Roadmap:** P2 — свой Overpass и ORS, BestTime, OSM Notes, iOS, EN/UA, админ-панель, размытие лиц, офлайн-режим.

## 15. Ограничения прототипа (честно указать в презентации)
- Толпы — эвристика + демо-данные, а не реальные замеры.
- Партнёры и ваучеры — демо.
- ИИ может ошибаться, поэтому всё помечается «niezweryfikowane».
- Покрытие только центра Кракова.
- WCAG проверен вручную (TalkBack или NVDA + клавиатура + контраст), без аудита.
